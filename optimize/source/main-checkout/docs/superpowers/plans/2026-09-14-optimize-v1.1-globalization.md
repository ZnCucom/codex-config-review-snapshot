# Optimize v1.1 Globalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generalize approved Optimize v1 into a backward-compatible global Codex context policy with lightweight and stateful modes, generic work units, safe global installation, deterministic repository initialization, and explicit v1 migration.

**Architecture:** Keep schema v1 and all v1 artifacts valid. Add a closed schema v2 plus generic templates, extend the existing CLI for init/migrate, isolate global filesystem ownership in `scripts/optimize_global.py`, and put mode selection in the concise skill/router rather than a large classifier.

**Tech Stack:** Python 3.11+ standard library, Git CLI, TOML front matter, Markdown, JSON, unittest, Windows and `core.autocrlf=true` clean-clone verification.

**Spec:** `docs/superpowers/specs/2026-09-14-optimize-v1.1-globalization-design.md`

## Global Constraints

- Stable v1 baseline is `e86b358aaa67250fc80a32864fb387fa9598ea14`; all 51 v1 tests remain passing.
- Teaching AI, real user-level Codex files, business code, public contracts, and v1 review artifacts remain read-only.
- Schema v1 stays supported; schema v2 is preferred for new stateful projects.
- L1/L2/L3 remain bounded to 8/12/4 KiB.
- `$HOME/.agents/skills` and the active `$CODEX_HOME/AGENTS*.md` follow current official OpenAI documentation.
- No third-party dependency, daemon, scheduler, database, background service, opaque memory, or automatic global rollout.
- Every feature or bug fix follows a witnessed RED/GREEN cycle and a focused commit.
