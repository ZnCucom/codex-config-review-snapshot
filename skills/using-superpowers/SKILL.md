# Using Skills on Demand

Skills are optional task capabilities, not a mandatory conversation-start workflow. A simple task can use no Superpowers skill at all. When the task can be completed directly and reliably, proceed.

Use a skill explicitly named by the user. Otherwise, select one only when its actual expertise, procedure or tools materially fit the task. Keywords, vague relevance and low-probability matches are insufficient. Read the selected instructions and only the references needed for the decision; do not chain unrelated skills or create a todo for every checklist item.

Respect higher-priority runtime, project and user instructions. Existing authorization for clear, reversible work remains valid. Clarify only material missing requirements or decisions, not permission already granted.

Use brainstorming for important unresolved design questions, debugging for actual diagnostic work, TDD where tests-first is useful, and proportionate verification for evidence. A plan does not automatically require delegation, a reviewer, a worktree or STATEFUL context.

For Codex-specific coordination principles, consult [codex-tools.md](references/codex-tools.md) when needed. Do not load other platform references in a Codex task.
